## `16 // ENGINEERING PRINCIPLES`

| Principle | Meaning |
|---|---|
| Architecture before complexity | Clear boundaries are more valuable than a random large stack. |
| Measure before optimizing | Performance work should target proven bottlenecks. |
| Security belongs in the request path | Validation, authentication and authorization are architectural concerns. |
| Production is a different environment | Local success does not prove production stability. |
| Real repository evidence matters | Concrete public work is stronger than decorative claims. |
| Tools support judgment | Frameworks and automation improve workflow but do not replace engineering reasoning. |
